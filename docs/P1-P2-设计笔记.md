# P1/P2 页面设计笔记（探索结论，实施时照此执行）

> 2026-10-12 P0 收口时沉淀。来源：lux_balance / auto_night_light 源码通读。

## P1 — lux_balance 页（`<lux-balance-page>`，id `luxbalance.main`）

### 数据面（全部已实证）
- 区域运行时：`hass.data["lux_balance"][entry_id]` → `ZoneRuntime`（runtime.py，832 行）
- 状态字段：`mode`（idle/active/calibrating/passthrough）、`cal_progress`（"准备中"/"基线（灯全灭）"/"上行 78%"/"下行 40%"，校准实时进度）、`target_lux`、`commanded_pct`、`lux_stale`、`decisions`（deque[str]，最近 50 条格式化决策行）、`last_decision.ambient_lux/needed_lux`、`zone_name`、`entry_id`、`light_entity`、`lux_entity`
- 曲线：`runtime.curve` → `Curve.points`（list[(pct, lux)]，含 (0,0) 锚点）、`.source`、`.max_lux`、`.slope_20_80`。⚠ diagnostics() 只暴露 max/slope，**REST 要直接读 curve.points**
- 校准启动：服务 `lux_balance.calibrate`（支持 entity_id 目标，见 \_\_init\_\_.py:76-126）或 `runtime.start_calibration()`；**没有取消校准的 API**（_cal_task 无公开 stop）——页面 v1 不做"停止"按钮
- 实体面：每区 light（虚拟灯）+ number（目标照度 10-500）+ button（校准）+ sensor（status，diagnostics 属性）

### 页面设计（计划已批的 IA）
- 区域卡 ×N：状态灯 + cal_progress（校准中 1s 轮询，空闲 5s）+ 目标照度（写 `number/set_value`）+ 立即校准（写 `lux_balance/calibrate`，entity_id=该区实体集合 `_zone_entities` 口径：registry 条目 + light + lux）
- 标定曲线：SVG 折线（cx- 系组件 + 内联 SVG），数据 = curve.points；无曲线 → 空态 + 校准引导按钮
- 决策日志：`decisions` 字符串表格化（等宽字体直接展示）

### REST（lux_balance 侧新增 web.py，照 Stockroom/WHA 模式）
- `GET /api/lux_balance/overview` → `{zones: [{entry_id, zone_name, mode, cal_progress, target_lux, commanded_pct, lux_stale, curve: {source, max_lux, slope_20_80, points}, decisions: [...], ambient_lux_est, needed_lux, light_entity, lux_entity}]}`（requires_auth + require_admin）
- 静态路径 `/lux_balance` → static/；panel-page.js 自定义元素 + registry 注册（hub 缺席回落独立面板——P0 README 契约）

## P2 — auto_night_light 页（`<anl-page>`，id `anl.main`）

### 数据面（已实证）
- `NightLightManager.machines: dict[entity_id, LightMachine]`（manager.py:131-144）：
  - `state: LightState`（9 态枚举 :116-128）：IDLE / TURN_ON_PENDING / PENDING / MATCHED / SETTING / VERIFIED / MISMATCH / OFFLINE / SKIPPED_OFF
  - `last_error`、`target (亮度,色温)`、`band_key`、`expected/applied`、`mismatch_steps`、`manual_override`（手动接管标记）
- 锚点/时刻表：`_night_anchor_times()`、`_anchor_modes()`、`_transition_bands()`（过渡带列表）、`_next_start_dt()`（下次锚点）
- 触发动作：服务 `trigger_now`（唯一运行时出口）
- 集成零实体平台——页面是其唯一可视化面（价值最高点）

### 页面设计
- 全局卡：当前时段/下一锚点（`_next_start_dt`）+ 立即触发按钮（`trigger_now` 服务）
- 逐灯卡片：状态机 chips（VERIFIED=绿 / MISMATCH=红 / manual_override=黄"手动接管"）+ mismatch_steps + target/applied
- 锚点时刻表表格：`_anchor_modes()` + 过渡带

### REST
- `GET /api/auto_night_light/snapshot`（manager 快照序列化；枚举用 `.value`）

## 通用（两页共用，P0 已就绪的壳契约）
- 注册：`hass.data.setdefault("fumiha_hub_registry", {})` + 描述符 + `hass.bus.async_fire("fumiha_hub_page_changed", ...)`；unload 时 pop + fire
- 页面模块：`window.FUMIHA.kit.defineOnce(name, class extends HTMLElement)`；`set hass` / connectedCallback（addTokens + startPolling）/ disconnectedCallback 停表
- 样式：tokens.css 的 fx-/cx- 组件类；写操作 ack 走 kit.ack
- 消费方不 import fumiha_hub；module_url 带 `?ver=<manifest 版本>`
- 测试：L1 stub 冒烟（REST handler+registry 注册）+ L2 Playwright（dev harness 加各页 fixture 路由）
